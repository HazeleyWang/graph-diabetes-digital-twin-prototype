# 项目小灶：边做边理解

这份笔记用于同步解释项目进展。每个阶段都回答五个问题：为什么做、输入是什么、实际操作是什么、期待看到什么、结果如何影响下一步。

## 0. 项目目标

我们希望用糖尿病患者的住院记录建立一个“小型医疗数字孪生原型”：先把每次住院表示为结构化特征，再把同一患者的多次住院及患者间的相似性表示为图，预测患者是否会在30天内再次入院。

这个项目不是为了证明图神经网络一定更强，而是为了展示完整的科研能力：临床问题定义、数据审计、防止泄漏、可靠基线、图表示、可解释性和诚实的局限性分析。

## 1. 数据与仓库准备（已完成）

### 为什么做

科研项目首先要可复现，并确保原始医疗数据不会被意外上传。

### 已完成

## 2. 第一轮数据审计（已完成）

### 为什么做

在建模前先确认数据规模、重复记录、目标比例和缺失值。否则模型可能只是在利用错误、泄漏或数据收集方式。

### 关键结果

- 101,766 次住院，71,518 位患者，50个变量。
- 没有重复 encounter ID，也没有完全重复的记录。
- 16,773 位患者有多次住院，占全部患者的23.45%；单个患者最多40次住院。
- 30天内再入院为11,357次，占11.16%，属于不平衡分类问题。
- `weight` 缺失96.86%，不适合进入主要模型。
- `A1Cresult` 和 `max_glu_serum` 中的 `None` 往往表示“没有检测”，它本身可能反映医疗过程，不能简单用均值填补。

### 如何理解

如果模型把所有人都预测为“不在30天内再入院”，准确率已经达到88.84%，但这个模型对临床完全没用。因此后续不能只汇报 accuracy，要重点看 AUROC、average precision、召回率和校准。

同一患者可能出现多次。如果随机按住院记录切分数据，同一人的一次住院可能在训练集，另一次在测试集，模型会间接“见过”测试患者。这叫 patient leakage，会让结果虚高。因此必须按患者编号整体切分。

## 3. 预测时间点与变量字典（当前阶段）

### 为什么做

预测必须回答“站在什么时间点，我们当时知道哪些信息”。我们把预测时点固定为患者出院时，目标是预测其未来30天是否再入院。

### 当前决策

- 可使用入院前历史、入院信息、住院过程和出院时已经知道的信息。
- `readmitted` 是未来结果，只能作为标签。
- `encounter_id` 只是流水号，不能用于预测。
- `patient_nbr` 只用于患者分组和构图，不能直接作为数值特征。
- `discharge_disposition_id` 可能直接表示死亡或临终关怀。这些患者无法发生普通再入院，直接把字段交给模型会产生捷径，因此只用于队列规则和敏感性分析。

### 期待结果

得到一个经过校验的50变量字典，为每个变量注明可用时间、建模角色和风险。下一步所有预处理和模型都遵守这个契约。

## 4. 下一阶段：患者级切分与表格基线

我们将先建立一个简单但可靠的表格模型，而不是直接上图神经网络。

### 为什么先做基线

图模型只有在严格相同的数据切分和指标下超过简单模型，才说明图结构提供了额外信息。否则复杂模型只是增加了工作量和过拟合风险。

### 计划

1. 按患者分成训练集、验证集和测试集。
2. 在训练集上学习缺失值、类别合并和编码规则。
3. 训练逻辑回归，得到透明的最低基线。
4. 再训练一个非线性树模型作为强表格基线。
5. 汇报 AUROC、average precision、校准和亚组表现。

之后才会构建患者—住院图，并判断图模型是否真正增加价值。
